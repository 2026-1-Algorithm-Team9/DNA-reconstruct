 DNA Short Read 재조립 — 컴파일 & 테스트 가이드
 (각 프로그램 빌드/실행법, 파라미터 조절, 벤치마크 CSV 뽑기)
════════════════════════════════════════════════════════════════════

──────────────────────────────────────────────────────────────────
0. 전제 — 이 프로젝트엔 "독립 실행 프로그램"이 여러 개다
──────────────────────────────────────────────────────────────────
각 .c 파일이 자기 main()을 가진 별개 프로그램이다. 한꺼번에 합쳐 빌드하지 말 것.

  프로그램                  | 구성 파일                        | 종류
  --------------------------|----------------------------------|----------------
  ① 조립 (메인 알고리즘)     | preIndex.c + preIndex_core.c     | de novo 조립
  ② Trivial 탐색 (벤치마크)  | trivial_search.c                 | reference 매핑
  ③ Simple Hash 탐색(벤치마크)| simple_hashing_search.c          | reference 매핑

 ※ ①만 파일 2개를 함께 컴파일한다(코어 분리 구조).
   ②③은 각각 파일 1개로 단독 컴파일한다.

 ※ 컴파일러: 맥/리눅스는 cc 또는 gcc, 윈도우는 gcc(MinGW).
   아래 예시의 cc 를 gcc 로 바꿔도 동일하게 동작한다.


──────────────────────────────────────────────────────────────────
1. ① 조립 (메인) — preIndex.c + preIndex_core.c
──────────────────────────────────────────────────────────────────
[컴파일] (파일 2개를 반드시 함께)
   cc -O2 -o run preIndex.c preIndex_core.c
   (윈도우: gcc -O2 -o run.exe preIndex.c preIndex_core.c)

[실행]
   ./run            (윈도우: run.exe)

[출력] 실험 조건 + 두 방식(Greedy / Consensus) 각각의
   복원율·속도·메모리 + 비교 요약.

[파라미터 조절] → preIndex_core.h 의 #define 값 수정 후 재컴파일
   - refLength            : 원본 길이 N (예 20000)
   - COVERAGE             : 커버리지 배수 (예 60)  → 리드 개수 자동 계산
   - fragLength           : 리드 길이 L (예 100)
   - K_MER                : 인덱스 k-mer 길이 (예 10)
   - DBG_K                : De Bruijn k-mer 길이 (예 15)
   - DBG_MIN_FREQ         : 에러로 간주할 저빈도 임계 (예 2)
   - ERROR_RATE_PERCENT   : 시퀀싱 에러율 % (0,1,2,3,5 …)
   ※ 값 바꾼 뒤 반드시 다시 cc -O2 -o run preIndex.c preIndex_core.c

[주의] DBG_K=15면 consensus가 잠깐 약 5GB 메모리를 쓴다.
   램이 적은 PC에서 "메모리 할당 실패"가 뜨면 DBG_K를 13으로 낮춰라
   (단 복원율이 다소 불안정해짐 — 트레이드오프).


──────────────────────────────────────────────────────────────────
2. ② Trivial 탐색 — trivial_search.c (단독)
──────────────────────────────────────────────────────────────────
[컴파일]
   cc -O2 -o trivial trivial_search.c
   (윈도우: gcc -O2 -o trivial.exe trivial_search.c)

[실행]
   ./trivial        (윈도우: trivial.exe)

[출력] 매핑 성공률 / 위치 정확도 / 탐색 시간.
   ※ 완전탐색이라 N=20000에서 약 1초 안팎 걸린다(원래 느린 게 정상).

[파라미터 조절] → trivial_search.c 상단 #define 수정 후 재컴파일
   - refLength, COVERAGE, fragLength : 조립과 동일하게 통일됨
   - ERROR_RATE_PERCENT  : 에러율 %
   - MISMATCH_THRESHOLD  : 매핑 시 허용 미스매치 수


──────────────────────────────────────────────────────────────────
3. ③ Simple Hash 탐색 — simple_hashing_search.c (단독)
──────────────────────────────────────────────────────────────────
[컴파일]
   cc -O2 -o simple simple_hashing_search.c
   (윈도우: gcc -O2 -o simple.exe simple_hashing_search.c)

[실행]
   ./simple         (윈도우: simple.exe)

[출력] 매핑 성공률 / 위치 정확도 / 탐색 시간(인덱스 구축 포함).
   ※ 해시 인덱스라 trivial보다 수십 배 빠르다.

[파라미터 조절] → simple_hashing_search.c 상단 #define
   - refLength, COVERAGE, fragLength : 조립/trivial과 통일됨
   - ERROR_RATE_PERCENT  : 에러율 %
   - MISMATCH_THRESHOLD  : 허용 미스매치
   - K_MER_SIZE          : 시드로 쓸 k-mer 길이 (예 4)

 ※ trivial 과 simple 은 데이터 생성 방식·파라미터가 통일돼 있어
   같은 조건에서 공정하게 속도·정확도를 비교할 수 있다.


──────────────────────────────────────────────────────────────────
4. 벤치마크 CSV 자동 뽑기 (발표/보고서용)
──────────────────────────────────────────────────────────────────
파라미터를 손으로 바꿔가며 여러 번 돌릴 필요 없이, 스크립트가
자동으로 재컴파일·측정해서 CSV로 떨궈준다. (맥/리눅스 bash 기준)

[A] 조립 벤치마크 (Greedy vs Consensus)
   bash make_graph_data.sh
   → 생성:
      graph_errorRate_vs_accuracy_(시간).csv   (에러율별 복원율)
      graph_coverage_vs_accuracy_(시간).csv    (커버리지별 복원율)

[B] 탐색 벤치마크 (Trivial vs Simple Hash)
   bash make_search_benchmark.sh
   → 생성:
      search_speed_(시간).csv      (에러율별 탐색 시간 + 배속 speedup)
      search_accuracy_(시간).csv   (에러율별 위치 정확도)

 ※ 두 스크립트 모두 끝나면 소스 파일을 원래대로 자동 복원한다.
 ※ 생성된 CSV는 엑셀/구글시트로 열어 그래프를 만들면 된다.
 ※ 윈도우에서 bash가 없으면 Git Bash에서 실행하거나, 손으로
    #define ERROR_RATE_PERCENT 값을 0/1/2/3/5로 바꿔가며 ②③①을
    각각 컴파일·실행해 숫자를 받아 적으면 된다.


──────────────────────────────────────────────────────────────────
5. 한글 깨짐 / 윈도우 관련 주의
──────────────────────────────────────────────────────────────────
 • 소스는 전부 UTF-8. Git Bash/콘솔에서 한글이 깨져 보이면
   실행 전에  chcp.com 65001  을 한 번 치거나 VS Code 터미널을
   UTF-8로 설정하면 된다. (출력만 깨지는 것이고 결과엔 영향 없음)
 • 난수는 bigRand()로 OS의 RAND_MAX 차이를 보정해, 맥/윈도우에서
   동일한 품질의 데이터가 생성된다(복원율/정확도 동일).


──────────────────────────────────────────────────────────────────
6. 빠른 점검용 — 한 번에 다 돌려보기 (맥/리눅스)
──────────────────────────────────────────────────────────────────
   # 조립
   cc -O2 -o run    preIndex.c preIndex_core.c && ./run
   # 탐색 2종
   cc -O2 -o trivial trivial_search.c           && ./trivial
   cc -O2 -o simple  simple_hashing_search.c    && ./simple

 결과 해석:
   - 조립: Greedy는 에러에 약하고, Consensus는 에러에도 복원율 유지.
   - 탐색: Trivial은 느리지만 정확, Simple Hash는 비슷한 정확도에 훨씬 빠름.
   - ※ 탐색의 "정확도(매핑/위치)"와 조립의 "복원율"은 의미가 다른 지표다.
        (탐색=위치 찾기, 조립=원본 복원) — 같은 표에 섞어 비교하지 말 것.
